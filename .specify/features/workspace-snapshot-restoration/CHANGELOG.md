- v1.2 — 2026-08-31 — POST-VERIFY FIX: "restored but invisible". A restore could report every window placed while the user saw nothing, because a hidden app (Cmd+H) or one whose windows live on another Space keeps a perfectly addressable AX window with a real frame — so `matchingWindows` found it, the move succeeded, and the pass counted it `placed` without ever surfacing it. Fix: `ApplicationLaunching` gains a best-effort `reveal(bundleID:)` (`AppLauncher` un-hides then `activate(options: [.activateAllWindows])`, which also pulls forward windows parked on another Space); `WorkspaceManager+Restore` calls it once per placement, *after* the move so the app is never flashed at its old position. A refused activation must not downgrade a placed window, so the reveal result is deliberately ignored for the summary. `MockApplicationLaunching` records `revealAttempts` and can force a failure via `unrevealableBundleIDs`. Four new tests in `FlowSnapTests/Core/Workspace/WorkspaceRestoreRevealTests.swift` (a suite of its own, kept separate so `WorkspaceManagerRestoreTests` stays under the `type_body_length` limit) pin: a placed window reveals its app; an unplaced (E4) or move-failed (E6) window never reveals; a refused reveal keeps the `placed` outcome. Also extracted the per-placement move into `place(_:placement:displays:options:)` and a single `move(...)` helper, which both removes the duplicated `do/catch` and brings `restore(_:displays:options:)` back under the 40-line `function_body_length` limit. Full suite now `265/265` across 36 suites; `xcodebuild build` clean; `swiftlint --strict` clean in owned files.
